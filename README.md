## 📋 Общее описание

**MAX BOT** - интеллектуальный телеграм-бот на основе **API MAX**, предназначенный для автоматизации бизнес-процессов и бесшовной интеграции с экосистемой **Битрикс24 (BX24)**.

### ✨ Ключевые возможности:
- 📨 Отправка сообщений через MAX бота
- 🔄 Автоматическая синхронизация с Битрикс24
- 📊 Работа с лидами и контактами
- 🔗 Интеграция с LMS платформами
- 🛡️ JWT-авторизация
- 🏥 Мониторинг состояния сервиса

**Версия:** `0.1.0`

## 🔐 Авторизация

Для работы с защищенными эндпоинтами требуется JWT токен.

### Получение токена:

```http
POST /v1/api/login
Content-Type: application/json

{
    "username": "admin",
    "password": "secret_password"
}
```
# Успешный ответ:

```json
{
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "bearer",
    "expires_in": 1800
}
```

### 🏥 1. Проверка состояния сервиса

Проверяет доступность сервиса и подключение к боту.

### Запрос
```http
GET /v1/api/health
```
#### Успешный ответ:

```json
{
    "status": "healthy",
    "timestamp": "2024-01-15T10:30:00Z",
    "bot_connection": true,
    "database": true,
    "version": "1.0.0"
}
```

#### Ошибка (503 Service Unavailable):

```json
{
    "status": "unhealthy",
    "timestamp": "2024-01-15T10:30:00Z",
    "bot_connection": false,
    "database": true,
    "errors": ["Bot connection failed"]
}
```

### 📨 2. Отправка сообщения

Отправляет персонализированное сообщение через бота.

### Запрос
```http
POST /v1/api/send-message
Authorization: Bearer <ваш_токен>
Content-Type: application/json
```

#### Тело запроса (JSON)

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|-----------|
| `text` | string | **Да** | Текст сообщения с поддержкой шаблонных переменных |
| `lead_id` | integer | **Да** | Идентификатор лида/пользователя в системе |
| `twilio_variables` | object | Нет | Переменные для замены в тексте сообщения |

#### Пример тела запроса
```json
{
    "text": "Привет, {{name}}! Ваш заказ #{{order_id}} готов к выдаче.",
    "lead_id": 12345,
    "twilio_variables": {
        "name": "Иван",
        "order_id": "ORD-789"
    }
}
```
#### Успешный ответ (200 OK)
```json
{
    "success": true,
    "message_id": "msg_abc123def456",
    "status": "sent",
    "timestamp": "2024-01-15T10:30:00Z"
}
```

#### 🚦 Коды состояния HTTP

| Код | Описание |
|-----|----------|
| 200 | Успешный запрос |
| 400 | Неверный формат запроса |
| 401 | Требуется аутентификация |
| 404 | Ресурс не найден |
| 429 | Слишком много запросов |
| 500 | Внутренняя ошибка сервера |
| 503 | Сервис недоступен |

### 3. 📨 Отправка сообщения (для Битрикс — GET)

```http
GET /v1/api/send-message-bx?text=Привет&lead_id=12345&twilio_variables={"name":"Иван"}
```

**Важно:** Платформа Битрикс не поддерживает обработку POST-запросов через стандартные механизмы в некоторых случаях (особенно при работе с AJAX и компонентами).
Для обхода этого ограничения используйте **GET-запросы** вместо POST, даже в тех случаях, когда по стандартам REST/RPC обычно применялся бы POST.

### 4. 📨 Отправка сообщения по шаблону SID

```http
GET /v1/api/send-id-sid-message-bx?sid_id=SID_123&lead_id=12345&twilio_variables=Europe;;https://example.com
```

**Важно:** Использует шаблоны из Google Таблицы.

### 5. 🔄 Синхронизация MAX ID с LMS

```http
GET /v1/api/sync-lms-max-id?phone=79161234567
```
**Важно:** Метод sync-lms-max-id выполняет синхронизацию MAX ID между системами

#### Логика интеграции MAX бот ↔ Битрикс ↔ LMS

## Общий процесс работы:

### 1. Поиск в MAX боте
- **Ключ поиска**: номер телефона
- **Результат**: получение `chat_id` пользователя

### 2. Поиск в Битрикс
- **Ключ поиска**: тот же номер телефона
- **Результат**: 
  - Найденный контакт (CONTACT) **или**
  - Найденный лид (LEAD)

### 3. Определение типа сущности
- **LEAD** → лид (потенциальный клиент)
- **CONTACT** → контакт (существующий клиент/партнер)
